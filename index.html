Era 2004 - 2012

Batch Processing Architecture

Arsitektur komputasi tradisional di mana data dikumpulkan dalam satu periode waktu tertentu (misal: harian, mingguan, atau bulanan), kemudian diproses secara serentak dalam satu kelompok besar (*batch*) terjadwal.

🧺
Analogi Mahasiswa

Mencuci Baju di Akhir Pekan: Anda tidak mencuci 1 kaos kotor setiap kali selesai ganti baju. Anda menunggu sampai keranjang cucian penuh di hari Minggu, baru mencuci semuanya sekaligus dengan mesin cuci. Sangat hemat detergen dan listrik, tapi kaos Anda tidak langsung bersih detik itu juga.

Alur Kerja Sistem (Workflow):

1 Ingestion: File log/transaksi diunggah secara periodik ke penyimpanan HDFS / Cloud Storage.
2 Schedule: Pengatur jadwal (Airflow / Cron Job) memicu proses pada jam 00:00 malam saat server sepi.
3 Compute: Apache Spark / MapReduce memecah komputasi ke puluhan worker node secara terdistribusi.
4 Output: Hasil agregasi disimpan ke Data Warehouse untuk dibaca dashboard pagi hari.
PySpark Batch Job (Sample) Scheduled Daily 
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("DailySalesBatch").getOrCreate()

# Baca seluruh data penjualan kemarin dalam 1 kali proses
df = spark.read.parquet("hdfs://cluster/raw_data/sales/2026-09-18/")

# Agregasi total omset per cabang toko
daily_report = df.groupBy("branch_id").sum("total_price")

# Simpan hasil ringkas ke Data Warehouse
daily_report.write.mode("overwrite").jdbc(url=dwh_url, table="fact_daily_sales")

⚖️ Kelebihan & Kekurangan

✔ Akurasi 100%: Seluruh data lengkap tersedia sebelum dihitung, tidak ada risiko data telat terlewat.
✔ Biaya Efisien: Server komputasi bisa dimatikan saat proses batch sudah selesai.
✖ Latensi Sangat Tinggi (Jam s/d Hari): Tidak berguna untuk kebutuhan tanggap darurat, fraud detection, atau live monitoring.

Teknologi Utama

Apache Hadoop HDFS MapReduce Apache Spark (Batch) Apache Hive Apache Airflow

Kasus Penggunaan Industri

Laporan rekonsiliasi akhir hari perbankan (*End-of-Day Settlement*), perhitungan gaji bulanan karyawan, kalkulasi pajak korporasi, dan pelatihan model Machine Learning berbasis data 5 tahun terakhir.

Era 2011 - 2015

Lambda Architecture (Dual Pipeline)

Diciptakan oleh Nathan Marz untuk menjawab kebutuhan *real-time* tanpa mengorbankan akurasi data. Arsitektur ini memecah data masuk menjadi **dua jalur paralel**: Speed Layer (cepat tapi estimasi) dan Batch Layer (lambat tapi presisi), lalu menggabungkannya di Serving Layer.

🍔
Analogi Mahasiswa

Restoran Cepat Saji (Kasir vs Akuntan): Kasir depan mencatat struk cepat-cepat dan memberi perkiraan antrean (Speed Layer). Namun di malam hari, manajer akuntansi menghitung ulang semua uang fisik di brankas dan mencocokkannya dengan pembukuan resmi (Batch Layer) untuk menimpa angka perkiraan kasir jika ada selisih.

1. Speed Layer (Hot)

Memproses data live via Kafka & Spark Streaming untuk menyajikan data beberapa detik terakhir.

2. Batch Layer (Cold)

Menyimpan data mentah permanen di HDFS dan menghitung ulang secara masif setiap malam.

3. Serving Layer

Menggabungkan hasil query dari Real-Time View dan Batch View saat dipanggil user.

⚠️ Masalah Terbesar Arsitektur Lambda (The Lambda Pain)

Duplikasi Logika Bisnis: Developer harus menulis kode rumus yang sama dua kali dalam dua bahasa/teknologi berbeda (misal: satu ditulis di Java untuk Apache Storm di Speed Layer, dan satu lagi di Scala/SQL untuk Hive di Batch Layer). Ketika ada perubahan rumus bisnis, sinkronisasi dua layer ini sering menghasilkan data yang tidak cocok (*data discrepancy*).

⚖️ Kelebihan & Kekurangan

✔ Terbaik di Masanya: Memberikan pandangan data real-time sekaligus menjamin kebenaran data historis.
✔ Fault Tolerant: Jika speed layer crash, batch layer malam hari akan memperbaiki semua data yang hilang.
✖ Kompleksitas Ekstrem: Memelihara dua infrastruktur berbeda secara bersamaan sangat mahal dan sulit di-debug.

Teknologi Utama

Apache Kafka Apache Storm / Flink Hadoop HDFS Apache HBase / Cassandra

Kasus Penggunaan Industri

Twitter Trending Topics awal tahun 2012, deteksi klik iklan penipuan (*ad-click fraud*), dan sistem rekomendasi e-commerce generasi pertama.

Era 2014 - Sekarang

Kappa Architecture (Stream-First)

Diusulkan oleh Jay Kreps (pencipta Kafka) sebagai solusi atas rumitnya arsitektur Lambda. Filosofi utamanya: "Hapus Batch Layer! Perlakukan semua data sebagai aliran (stream) tunggal tiada akhir." Data historis hanyalah stream masa lalu yang bisa diputar ulang (*replay*).

📹
Analogi Mahasiswa

Rekaman CCTV 24 Jam: CCTV merekam terus tanpa jeda. Jika Anda ingin melihat apa yang terjadi detik ini, tonton live feed-nya. Jika ingin tahu siapa yang mencuri helm minggu lalu, Anda tidak butuh kamera baru—cukup *rewind* (putar balik) rekaman CCTV yang sama ke tanggal kejadian.

Bagaimana Cara Kerja "Data Reprocessing" di Kappa?

1. Single Codebase: Hanya ada satu kode pengolahan (misal: Apache Spark Streaming atau Flink).
2. Append-Only Log: Semua event masuk disimpan di Kafka dengan masa simpan lama (*long retention*).
3. Replay from Offset 0: Jika rumus bisnis diubah, hidupkan instance baru dari kode streaming Anda, lalu arahkan pembacaan ke awal log (Offset 0). Selesai!
Spark Structured Streaming (Single Pipeline) Continuous Logic 
# Membaca dari Kafka secara real-time maupun historical replay
stream_df = spark.readStream \
    .format("kafka") \
    .option("subscribe", "live-trades") \
    .option("startingOffsets", "earliest") \
    .load()

# Logika yang sama untuk data live maupun data replay
processed = stream_df.select(from_json(col("value"), schema).alias("data")) \
    .groupBy(window(col("data.timestamp"), "1 minute"), col("data.symbol")) \
    .agg(avg("data.price").alias("vwap"))

⚖️ Kelebihan & Kekurangan

✔ 1 Basis Kode: Tidak ada duplikasi kode logika. Perawatan sistem jauh lebih sederhana.
✔ Konsistensi Data: Tidak ada perbedaan hitungan antara data real-time dan data historis.
✖ Mahal di Storage Log: Menyimpan seluruh riwayat log bertahun-tahun di Kafka membutuhkan biaya storage yang besar.

Teknologi Utama

Apache Kafka / Redpanda Apache Flink Spark Structured Streaming ClickHouse

Kasus Penggunaan Industri

Uber surge pricing & routing real-time, sistem deteksi fraud transaksi instan di fintech / perbankan, dan monitoring IoT armada logistik bergerak.

Era 2020 - Sekarang (Standar Industri)

Lakehouse Medallion Architecture

Standar emas industri modern yang dipopulerkan oleh Databricks dan open-source formats seperti Apache Iceberg & Delta Lake. Arsitektur ini menyatukan kelebihan Data Lake (murah, fleksibel) dengan Data Warehouse (transaksi ACID, kualitas data terjamin).

🚰
Analogi Mahasiswa

Filtrasi Air Minum 3 Tahap:
1. Bronze (Air Sumur): Air tanah mentah ditampung apa adanya (masih ada pasir dan daun).
2. Silver (Filter Karbon): Air disaring, kuman dan pasir dibuang, tapi belum dikemas.
3. Gold (Air Mineral Galon): Air siap minum yang sudah higienis, berstandar mutu SNI, dan siap disajikan ke meja konsumen.

🥉 BRONZE TIER (Raw Ingestion Zone) Append-Only

Menampung data mentah apa adanya dari Kafka, API, atau IoT. Tidak ada filter, tidak ada perubahan tipe data. Berfungsi sebagai jejak audit abadi.

🥈 SILVER TIER (Cleansed & Enriched Zone) Enterprise Truth

Data dibersihkan: null values ditangani, deduplikasi data kembar, schema enforcement, dan join antar tabel relasional. Siap untuk dieksplorasi Data Scientist.

🥇 GOLD TIER (Business / Curated Mart) High Performance

Data agregat berkinerja tinggi, star schema / dimensional modelling. Dirancang khusus untuk dashboard BI eksekutif dan reporting cepat.

⚖️ Kelebihan & Kekurangan

✔ Mendukung ACID Transactions: Tidak ada file korup jika terjadi kegagalan tulis di tengah jalan.
✔ Unified Batch & Streaming: Bisa ditulis via streaming tapi dibaca via batch SQL secara bersamaan.
✔ Time Travel: Kemampuan melihat kondisi data pada snapshot masa lalu untuk audit & debugging.

Teknologi Utama

Apache Iceberg Delta Lake MinIO S3 / HDFS dbt (Data Build Tool) Trino / Starburst

Kasus Penggunaan Industri

Netflix, Shopee, Tokopedia, Gojek, dan perbankan modern yang membutuhkan repositori data terpusat untuk analitik gabungan BI dan AI/ML.
